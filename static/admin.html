Faceplate
Aruba
AOS-CX

Direct AOS-CX API. Username and password are exchanged for a session token, and later requests send that token. The faceplate is a 6200F and reads ports 1/1/1 through 1/1/12. ClearPass can add client detail. This faceplate does not call Mist.

Aruba Roles

AOS-CX faceplate only. The role name must match the role the switch applies. The EX faceplate uses the Juniper/Mist Roles and Port profiles sections. Legend order 0 hides a role. Empty color means no light. A link with no authenticated client stays dark, even when the Port up role has a color. Choose one Port up, one Port down, and one Multiple roles role.

Juniper/Mist
Mist

API token for the EX faceplate. Mist sends it on each request. Create one in the Mist UI. The token is required for that faceplate. The AOS-CX faceplate does not call Mist, and this demo does not open a Junos session.

EX switch

Juniper EX4000 through Mist only. Enter the Mist site and the switch MAC. The API token is in the Mist section above. Ports 0–11 (ge-0/0/0–ge-0/0/11, or mge- on the 12MP) light from the Mist role when a client has one, and from the port profile otherwise. SFP, management, and console stay dark. A link with no client stays dark. See SUPPORT.md.

Port profiles

EX faceplate only. The name must match the port profile Mist applied (port_usage, the same string as usage and reportedProfile, for example dot1x-only). This list is not the Aruba role list and not the Roles list below. A connected client with no Mist role lights this profile. A client that has a role uses the Roles section instead. A link with no client stays dark. A profile that is not in this list still lights gray so you can add it. Legend order 0 hides it from the legend.

Roles

EX faceplate only. These are the radius-group roles from the Mist switch template, such as EMPLOYEE and IOT. The name must match the role Mist applies to the client. A client with a role lights that color. A client with no role keeps the port profile color. A role that is not listed yet still lights gray. Legend order 0 hides it from the legend. AOS-CX does not use this list.

ClearPass

Used only by the AOS-CX faceplate, and only as extra client detail. Client ID and secret are exchanged for a bearer token, which fills device name, type, and address on that popover. The demo runs without it. Port color still comes from the switch role. The EX faceplate does not call ClearPass.
