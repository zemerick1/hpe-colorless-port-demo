AOS-CX

Direct AOS-CX API. Username and password are exchanged for a session token, and later requests send that token. ClearPass can add client detail. This faceplate does not call Mist.

Supported models: 6200F 12-port, 6300F 24-port (JL666A), and 6300M 24-port (JL660A). The faceplate follows the switch. The 24-port photos fill the same frame. Other Aruba models stay blank.

Aruba Roles

AOS-CX faceplate only. The name is the role on the switch. The jack uses this color only when that name matches the role the switch applied. The port popup shows the switch role, including a role that is not in this list, and that port stays grey. The label is the legend text. The EX faceplate uses the Juniper/Mist Roles and Port profiles sections. Legend order 0 hides a role. Empty color means no light. A link with no authenticated client stays dark, even when the Port up role has a color. Choose one Port up, one Port down, and one Multiple roles role.

Juniper/Mist
EX polling

The EX faceplate polls one source. Pick Mist or Junos, then Save. Both sets of details can stay filled in. Only the selected source is polled.

Mist

API token for Mist polling. Mist sends it on each request. Create one in the Mist UI. Choose Mist under EX polling and Save to use it. The AOS-CX faceplate does not call Mist.

Junos

Direct Junos REST. The switch must already have system services rest https. The default port is 3443. A blank password on Save keeps the stored password. A session's firewall filter is the access name. Choose Junos under EX polling and Save to poll this switch. Leave the host filled in when you switch back to Mist.

EX switch

Juniper EX4000 through Mist. Enter the Mist site and the switch MAC. The API token is in the Mist section. Choose Mist under EX polling and Save to poll this switch. Ports 0–11 (ge-0/0/0–ge-0/0/11, or mge- on the 12MP) light from the Mist role when a client has one, and from the port profile otherwise. SFP, management, and console stay dark. A link with no client stays dark. See SUPPORT.md.

Port profiles

EX faceplate only. The name must match the port profile Mist applied (port_usage, the same string as usage and reportedProfile, for example dot1x-only). This list is not the Aruba role list and not the Roles list below. A connected client with no Mist role lights this profile. A client that has a role uses the Roles section instead. A link with no client stays dark. A profile that is not in this list still lights gray so you can add it. Legend order 0 hides it from the legend.

Roles

EX faceplate only. On Mist this name is a radius-group role. On Junos it is the ethernet-switching firewall filter on the session, and Mist pushes that filter only after the role is applied to a Switch Policy. A role left off every Switch Policy never reaches the switch. A client with a name lights that color. A Mist client with no role keeps the port profile color. Junos has no port profile. A name that is not listed yet still lights gray. Legend order 0 hides it from the legend. AOS-CX does not use this list. Load fills this form. Save keeps it.

ClearPass

Used only by the AOS-CX faceplate, and only as extra client detail. Client ID and secret are exchanged for a bearer token, which fills device name, type, and address on that popover. The demo runs without it. Port color still comes from the switch role. The EX faceplate does not call ClearPass.

Roles and firewall filters

AOS-CX has a port-access role. The jack color on that faceplate is the role the switch applied. The port popup shows that role. Admin matches it by name. The label is only the legend. A role that is not in Admin stays grey. That faceplate still reads the switch directly.

The AOS-CX faceplate follows the switch. Supported models are the 6200F 12-port, the 6300F 24-port (JL666A), and the 6300M 24-port (JL660A). The 24-port photos fill the same frame, so the jack map stays put. Any other Aruba model stays blank.

Junos has no role object. Mist does. Mist pushes an ethernet-switching firewall filter with the role's name only after that role is applied to a Switch Policy. In Mist, that firewall filter is the Switch Policy. A role that is not on a Switch Policy is never pushed, so the filter and the role never appear on the Junos device. When the policy is applied, the switch has a filter of that name:

firewall {
    family ethernet-switching {
        filter EMPLOYEE { ... }
        filter IOT { ... }
    }
}

On the EX faceplate the label follows the live source. Mist says Role. Direct Junos says Firewall filter. The name and the color come from the same list.

A port profile is Mist's port usage, for example dot1x-only. It colors a Mist client only when no role was applied. The Junos path does not use port profiles.

Under Juniper/Mist, EX polling chooses Mist or Junos. Save applies that choice. Both can stay filled in. The faceplate polls only the one you chose.
